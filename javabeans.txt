Arrays
🔹 1. Declaring and Defining Arrays (Java)

An array is a collection of elements of the same type stored in contiguous memory.

 ✅ Declaration
You just declare the array reference (no memory allocated yet):

```java
int[] arr;
```

or

```java
int arr[];
```

 ✅ Definition (Initialization)

Now you allocate memory to the array:

```java
arr = new int[5];
```

 ✅ Declaration + Definition together

```java
int[] arr = new int[5];
```

 ✅ Declaration + Initialization with values

```java
int[] arr = {10, 20, 30, 40, 50};

🔹 2. Primitive Arrays

Primitive arrays store **primitive data types** like `int`, `char`, `float`, `double`, `boolean`.

 Example:

```java
int[] numbers = {1, 2, 3, 4, 5};

for (int i = 0; i < numbers.length; i++) {
    System.out.println(numbers[i]);
}

Key Points:

* Stores actual values
* Faster performance
* Default values:

  * int → 0
  * float → 0.0
  * boolean → false
  * char → '\u0000'

 Example with default values:

```java
int[] arr = new int[3];
System.out.println(arr[0]); // 0
🔹 3. Object Arrays

Object arrays store **references (addresses)** of objects, not actual values.

Example with String:

```java
String[] names = {"John", "Alice", "Bob"};

for (String name : names) {
    System.out.println(name);
}

 Example with custom class:

```java
class Student {
    String name;
    
    Student(String name) {
        this.name = name;
    }
}

public class Main {
    public static void main(String[] args) {
        Student[] students = new Student[2];
        
        students[0] = new Student("Ram");
        students[1] = new Student("Sam");
        
        for (Student s : students) {
            System.out.println(s.name);
        }
    }
}
 Primitive vs Object Arrays (Interview Table)

| Feature       | Primitive Array | Object Array      |
| ------------- | --------------- | ----------------- |
| Stores        | Actual values   | Object references |
| Example       | `int[] arr`     | `String[] arr`    |
| Default value | 0, false, etc.  | null              |
| Memory        | Less            | More              |
| Performance   | Faster          | Slightly slower   |

Inheritance:
   🔹 1. Is-A Relationship (Inheritance)

Represents inheritance → one class is a type of another class.

 ✅ Example:

```java
class Animal {
    void sound() {
        System.out.println("Animal makes sound");
    }
}

class Dog extends Animal {
    void bark() {
        System.out.println("Dog barks");
    }
}
👉 Here:
> Dog is-a Animal

  class Employee {
    void work() {
        System.out.println("Working...");
    }
}

class Tester extends Employee {
    void test() {
        System.out.println("Testing application");
    }
}
Here:

Tester is-a Employee

✔️ Key Point:

* Achieved using `extends`
* Supports code reuse

---

🔹 2. Has-A Relationship (Composition)

Represents ownership → one class has an object of another class.

 ✅ Example:

```java
class Engine {
    void start() {
        System.out.println("Engine starts");
    }
}

class Car {
    Engine engine = new Engine(); // Has-A relationship

    void drive() {
        engine.start();
        System.out.println("Car is moving");
    }
}

👉 Here:
> Car has-a Engine
Banking System:
class Account {
    void accountDetails() {
        System.out.println("Account details");
    }
}

class Customer {
    Account acc = new Account(); // Has-A

    void show() {
        acc.accountDetails();
    }
}
Here
Customer has-a Account
 ✔️ Key Point:
* Achieved by creating object inside class
* Used for code modularity & reuse

 🔹 3. Inheritance using `extends` Keyword

Used for class-to-class inheritance.

✅ Example:

```java
class Parent {
    void show() {
        System.out.println("Parent method");
    }
}

class Child extends Parent {
    void display() {
        System.out.println("Child method");
    }
}
Example: Employee System
  class Employee {
    String name;

    void work() {
        System.out.println("Employee working");
    }
}

class Developer extends Employee {

    void code() {
        System.out.println("Writing code");
    }
}

public class Main {
    public static void main(String[] args) {
        Developer dev = new Developer();
        dev.work();   // inherited
        dev.code();   // own method
    }
}
Inheritance allows a child class to reuse properties and methods of a parent class using extends.

  ✔️ Features:
* Single inheritance supported
* Multilevel inheritance supported
* Java does NOT support multiple inheritance (via classes)

🔹 4. Inheritance using `implements` Keyword

Used when a class implements an **interface**.

 ✅ Example:

```java
interface Animal {
    void sound(); // abstract method
}

class Dog implements Animal {
    public void sound() {
        System.out.println("Dog barks");
    }
}
Example: Payment System
interface Payment {
    void pay();
}

class CreditCardPayment implements Payment {
    public void pay() {
        System.out.println("Paid using Credit Card");
    }
}

class UpiPayment implements Payment {
    public void pay() {
        System.out.println("Paid using UPI");
    }
}

Here Multiple payment methods using same interface
 ✔️ Key Points:
* Supports multiple inheritance
* Methods must be implemented
* Uses `implements` keyword


Abstraction:
 🔹 1. Abstraction using Abstract Classes

Abstract class = partial abstraction (can have both abstract + concrete methods)

 ✅ Example:

```java
abstract class Animal {
    abstract void sound(); // abstract method

    void sleep() {
        System.out.println("Sleeping...");
    }
}

class Dog extends Animal {
    void sound() {
        System.out.println("Dog barks");
    }
}
Example: Payment System
  abstract class Payment {

    // Abstract method
    abstract void makePayment(double amount);

    // Concrete method
    void paymentStatus() {
        System.out.println("Payment processing...");
    }
}

class CreditCardPayment extends Payment {

    void makePayment(double amount) {
        System.out.println("Paid " + amount + " using Credit Card");
    }
}

class UpiPayment extends Payment {

    void makePayment(double amount) {
        System.out.println("Paid " + amount + " using UPI");
    }
}

public class Main {
    public static void main(String[] args) {
        Payment p = new CreditCardPayment();
        p.paymentStatus();
        p.makePayment(1000);
    }
}
Abstract class defines common behavior and forces subclasses to implement specific methods.

✔️ Key Points:

* Cannot create object of abstract class
* Can have:

  * abstract methods
  * normal methods
* Uses `extends`



🔹 2. Abstraction using Interfaces

Interface = 100% abstraction (traditionally)
 ✅ Example:

```java
interface Animal {
    void sound();
}

class Dog implements Animal {
    public void sound() {
        System.out.println("Dog barks");
    }
}
Example: Login System
interface Login {
    void authenticate();
}

class GoogleLogin implements Login {
    public void authenticate() {
        System.out.println("Login via Google");
    }
}

class FacebookLogin implements Login {
    public void authenticate() {
        System.out.println("Login via Facebook");
    }
}

  Key Points:

* Only method declarations (by default abstract)
* Supports multiple inheritance
* Uses `implements`


  Abstract Class vs Interface (Very Important)

| Feature              | Abstract Class      | Interface                                        |
| -------------------- | ------------------- | ------------------------------------------------ |
| Methods              | Abstract + Concrete | Abstract (default/static allowed in modern Java) |
| Keyword              | `extends`           | `implements`                                     |
| Multiple Inheritance | ❌ Not supported     | ✅ Supported                                      |
| Variables            | Any type            | `public static final`                            |
| Object creation      | ❌ Not allowed       | ❌ Not allowed                                    |

Encapsulation:
Encapsulation means:
Wrapping data (variables) and code (methods) together into a single unit (class) and restricting direct access using access modifiers.

* Protects data (security 🔒)
* Controls access (using getters/setters)
* Improves maintainability

🔹 Real-Time Example: Bank Account
 ✅ Java Code

```java
class BankAccount {

    // Private variables (data hiding)
    private String accountHolder;
    private double balance;

    // Setter method
    public void setAccountHolder(String name) {
        accountHolder = name;
    }

    // Getter method
    public String getAccountHolder() {
        return accountHolder;
    }

    // Setter with validation
    public void setBalance(double bal) {
        if (bal >= 0) {
            balance = bal;
        } else {
            System.out.println("Invalid balance");
        }
    }

    // Getter method
    public double getBalance() {
        return balance;
    }
}

🔹 Main Class

```java
public class Main {
    public static void main(String[] args) {

        BankAccount acc = new BankAccount();

        acc.setAccountHolder("John");
        acc.setBalance(5000);

        System.out.println("Name: " + acc.getAccountHolder());
        System.out.println("Balance: " + acc.getBalance());
    }
}


* Variables are private → cannot access directly
* Access is given via:

  * Getter → read data
  * Setter → update data (with validation)

🔹 EASY Example (Very Simple)

```java
class Student {
    private int marks;

    public void setMarks(int m) {
        marks = m;
    }

    public int getMarks() {
        return marks;
    }
}


* `marks` is hidden
* Access only through methods

  🔥 Without Encapsulation (Bad Practice ❌)

```java
class Student {
    public int marks;
}
```

👉 Anyone can directly modify:

```java
s.marks = -100; // invalid but allowed ❌

 🔥 With Encapsulation (Good Practice ✅)

```java
public void setMarks(int m) {
    if (m >= 0) {
        marks = m;
    }
}


👉 Now invalid data is controlled ✅

 Encapsulation is the process of hiding data using private variables and providing controlled access through public getter and setter methods.
🔹 Key Points to Remember

* Use private variables
* Use public getters/setters
* Provides data security + validation
